# ネイティブ・ローカルエージェント（Claude CLI 不要）

[English](NATIVE_AGENT.md) · [한국어](NATIVE_AGENT.ko.md) · 日本語 · [简体中文](NATIVE_AGENT.zh-CN.md)

チャットの 1 ターンは `manvi run` が実行します。ローカル Ollama、OpenAI 互換 API、
Claude チャットがこの経路です。一回きりの補完・埋め込み・キャプションと Ollama 管理だけが
DevPrism に残ります。現行の説明は [English](NATIVE_AGENT.md) が基準です。

## 有効化の手順

1. Ollama をインストールして起動し、**ツール呼び出し（tool calling）対応**のモデルを
   取得します:
   ```bash
   ollama pull llama3.1      # または qwen2.5, mistral-nemo, …
   ```
   （ツール呼び出し非対応の小型モデルは会話はできますがツールを使えません。）
2. DevPrism で: **設定 → プロバイダー（Provider）→「ネイティブ・ローカルエージェント
   （Claude CLI 不要）」**。
3. （任意）同じパネルで Ollama のエンドポイント／モデルを OpenAI 互換プロバイダーとして
   設定します。設定しない場合、ランタイムは既定の `http://localhost:11434` と最初に
   インストールされたモデルを使用します。

トグルがオンのときチャットはネイティブランタイムを使用し、クラウドプロバイダーはオフの
ときのみ使用されます。

## Claude モデル

モデル選択には Opus、Sonnet、Haiku、Opus Plan があります。Opus、Sonnet、Haiku は
それぞれ `claude-opus-5-5`、`claude-sonnet-5-5`、`claude-haiku-5-5` に対応します。
Opus Plan はカタログ ID ではありません。セッションモデルが Opus、heavy ティアが Sonnet
なので、Opus がターンを計画し Sonnet が書きます。advisor ティアは Opus のままで、
キャッシュキーは選択肢の文字列 `opusplan` のままです。ホストは、そのティアの既定の入力
価格が選んだモデルより高い場合にだけ Manvi のティアを固定するため、Sonnet のチャットが
Opus や Fable の補助呼び出しを始めることはありません。effort は `low`、`medium`、`high`
のいずれかです。Anthropic キーは設定に保存されたものを使い、保存されていなければアプリ
自身の環境の `ANTHROPIC_API_KEY` を使います。`bun run dev:desktop` は、隣のチェック
アウトの Go ソースがディスク上のバイナリより新しいとき Manvi サイドカーを再ビルドします。

## できること

- `manvi run` がツールループを実行します。チャット UI・差分・「保持／取り消し」は
  そのままです。下のツール一覧は以前の Rust ループの説明で、現行のツールは Manvi
  のハーネスと DevPrism MCP です。
- **ツール:** `Read`、`Write`、`Edit`（`replace_all` 対応）、`LS`、`Grep`（`glob`/
  `case_sensitive` の絞り込み）、`Glob`、`Bash`（プロジェクト内で実行し `.venv` を有効化）。
  すべてのファイルアクセスはプロジェクトディレクトリ内に限定されます。これらの組み込み
  ツールに加え、プラグインレジストリの厳選されたサブセットも公開します — ナレッジベース
  検索、履歴書シンセシス／ギャップ分析／コンパイル、保護付き履歴書ドキュメント編集
  （`resume_doc_*`、`resume_variant_*`）。各パックはツール単位で公開可否を選びます
  （[PLUGINS.md](PLUGINS.md) を参照）。
- **プロジェクトコンテキスト:** マスター／指示ファイル、プロジェクトマップ、インストール
  済みスキルを自動検出します（[CONTEXT_FILES.md](CONTEXT_FILES.md) を参照）。
- **メモリ:** チャットタブごとに会話を記憶します。
- **ビジョン:** 貼り付けた画像は、ビジョン対応モデル（`llava`、`llama3.2-vision` など）に
  送信されます。
- **ストリーミング:** テキスト／思考の差分は IPC を越える前に Rust 側で統合されます
  （約 40ms または 1KiB のウィンドウ）。出力の細かいローカルモデルでもチャット UI が
  あふれません。

## チューニング（ネイティブ有効時：設定 → プロバイダー）

- **コンテキストウィンドウ（`num_ctx`）** — モデルが一度に「見られる」量（既定 8192）。
  大きいほどメモリ／VRAM を消費します。低スペック機では下げ、長い文書／会話では上げます。
- **温度（Temperature）** — 既定 0.4（低いほど編集がより決定論的）。

## 注意・制限事項

- ツール呼び出しの品質はモデルに依存します。ごく小さい非ツールモデルより `llama3.1` /
  `qwen2.5` / `mistral-nemo` を推奨します。
- 会話メモリはプロセス内に保持されます（「新しいチャット」／タブを閉じると消去され、
  アプリ再起動をまたいだ永続化はまだ行いません）。
- 出力は応答単位です（トークン単位のストリーミングではなく、チャット UI のメッセージ
  モデルに合わせています）。
